# Критерий итогового решения: обоснование безопасности

**Вывод:** предложенная политика обеспечивает G-01…G-05 в описанной модели при A-01…A-06. Обоснование опирается на [цели](../contractor_side/security_objectives/SECURITY_GOALS.md), [предположения](../contractor_side/security_objectives/SECURITY_ASSUMPTIONS.md), [DFD](../contractor_side/architecture_policy/POLICY_DFD.md) и [контракты сообщений](../contractor_side/architecture_policy/MESSAGE_CONTRACTS.md). Это обоснование проектной модели; развёрнутый экземпляр должен отдельно подтвердить гарантии платформы и физической схемы.

## Начальное состояние

По умолчанию маршруты закрыты. При первом запуске нет активного профиля и все климатические допуски сняты. При последующем запуске T может загрузить ранее принятый профиль из своего хранилища; до свежего локального измерения и нового разрешения допуски остаются снятыми. У M нет активных сеансов, а буферы выдачи пусты. У T нет команды уборки с непроверенным или неподтверждённым физическим результатом, отмеченным как установленный факт.

## Почему цели сохраняются

| Цель | Аргумент сохранения при переходах                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Критические предположения |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| G-01 | Единственный переход изменения активного профиля — принятие T из F-03 после проверки диапазонов, срока и идентификатора. F-04 не изменяет профиль и не управляет выходами. Только C по F-05 может выдать допуски F-06; один тепловой режим и независимая блокировка делают несовместимыми два физических допуска. Срок каждого допуска ограничен; истечение, потеря C или срабатывание соответствующей защиты снимает допуск. Ложное показание способно повлиять на выбор допустимого режима, но не расширяет полномочия и не обходит независимую защиту. | A-01, A-03, A-06          |
| G-02 | Камера и датчик движения имеют цифровой выход только к M. Единственная точка выдачи живого видео и отметок — F-09 в локальном сеансе, привязанном к аутентифицированной панели. Только запрос панели создаёт сеанс; движение изменяет буфер отметок, кадр не меняет авторизацию. Закрытие, потеря канала и истечение срока прекращают выдачу. У M нет маршрута к сервису или колонке.                                                                                                                                                                     | A-01, A-02, A-04, A-06    |
| G-03 | Канал K→Q принимает только `VoiceIntent(start/stop)`. Q выводит только ограниченное намерение для связанного W, а T направляет его по F-07. Действия профиля, климата и наблюдения требуют иных типов и идентичностей; у K нет этих прав. Даже произвольное голосовое намерение остаётся внутри выделенного полномочия.                                                                                                                                                                                                                                   | A-01, A-06                |
| G-04 | T — единственный писатель состояния заявки. Посторонний, поздний и несопоставленный отчёты не меняют запись; истечение срока завершает ожидание как `Unconfirmed`. `DeviceReport` остаётся отчётом, в том числе если W отвечает недостоверно. Колонка может озвучить что угодно, но не может изменить состояние T, читаемое панелью по F-08.                                                                                                                                                                                                              | A-01, A-02, A-06          |
| G-05 | Разрыв F-01 не инвалидирует принятый профиль и не является предусловием ни одного локального перехода. Климат использует F-04…F-06, наблюдение — F-09…F-10, уборка — локальные части F-02/F-03 и F-07/F-08, музыка не имеет межкомпонентного потока. При исправных локальных участниках и выделенных ресурсах отсутствие ответа N/сервиса не блокирует ни один из этих переходов.                                                                                                                                                                         | A-01, A-05, A-06          |

По индукции свойства безопасности сохраняются при любом количестве допустимых шагов: начальное состояние удовлетворяет инвариантам, описанные переходы их сохраняют, а сообщения вне политики не получают привилегированного эффекта. G-05 — свойство доступности, а не только инвариант: вывод о продолжении сценариев дополнительно опирается на исправность и своевременность их локальных участников по A-05.

## Остаточные эффекты

- Сервис может задержать или не доставить изменение профиля; сохранённый профиль продолжит действовать.
- Датчики могут выдавать ложные показания, камера — неверные кадры; цели ограничивают распространение данных и пределы управления, но не устанавливают физическую истинность входов.
- Колонка может инициировать допустимую уборку или потерять функцию музыки; пылесос может не выполнить команду. Жилец может проверить канонический статус на панели, где отчёт помечен как сообщение устройства.

Проверяемые ожидания для заказчика собраны в [приёмочных случаях](VERIFICATION_CASES.md).
