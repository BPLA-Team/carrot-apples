# Политика архитектуры: домены, стоимость и обоснование

См. [цветную DFD](POLICY_DFD.md) и [спецификацию сообщений](MESSAGE_CONTRACTS.md). Физических устройств по-прежнему девять. В D-01 выделяем изолированные роли; аппаратная блокировка из A-03 — часть защитного контура, а не отдельная пользовательская функция.

- **Красный — недоверенный.** Произвольные данные, сбои или молчание не дают дополнительных полномочий. Помещение в этот домен не означает отсутствие изоляции.
- **Зелёный — доверенный.** Малое ядро T принудительно соблюдает маршруты и владение состоянием; аутентичность канала опирается на платформу.
- **Оранжевый — повышающий.** Узкие проверяемые блоки Q, M и C преобразуют недоверенный ввод в строго ограниченное действие. Они входят в базу доверия вместе с T.
- **Серый — внешний участник.** Веб-интерфейс жильца — доверенная сторона сквозного обмена в объёме A-02. Внешний сервис — недоверенный посредник: он передаёт запросы и ответы, но не получает ключей обмена и не может отдавать команды устройствам напрямую. Оба участника находятся за пределами домашней LAN.

Шкала стоимости **включения в базу доверия**: **1** — малый конечный автомат или статическая проверяемая конфигурация; **2** — проверка протокола, прав и жизненного цикла; **3** — значительная кодовая база, специализированная обработка или проверка аппаратного контура. Это порядковые оценки сложности разработки и проверки, а не денежная смета. Для недоверенного домена оценка показывает цену, которой избегаем; изоляция всё равно требует настройки и тестов.

| ------------------------------------------- | ------------ | --------: | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 / N: шлюз к сервису                    | Недоверенный |         3 | Переносит подписанные запросы профиля и защищённые сообщения наблюдения и статуса. Не определяет полномочия и не расшифровывает наблюдение или статус. |
| D-01 / R: автоматика                        | Недоверенный |         2 | Сравнивает значения с уставками. Любое её решение остаётся предложением до проверки T/C.                                                                |
| D-01 / T: монитор, профиль, реестр статусов | Доверенный   |         2 | Единственный владелец активного профиля и канонического журнала уборки. Проверяет маршруты и связи состояний, не обслуживает видео и внешние протоколы. |
| D-01 / Q: проверка запросов                 | Повышающий   |         2 | Верифицирует подпись, полномочия и свежесть профиля; преобразует голосовой запрос в ограниченный тип команды на привязанный пылесос.                    |

| D-01 / C: ограничитель климата и блокировка | Повышающий   |         3 | Связывает команды с физическими разрешениями через проверяемый интерфейс A-03. Требуются стендовые проверки разрыва разрешения и независимых защит.     |
| D-02 / K: колонка                           | Недоверенный |         3 | Распознавание и плеер слишком велики для базы доверия. Голосовые намерения ограничены Q; музыка не использует хаб.                                      |
| D-03 / D: датчик движения                   | Недоверенный |         1 | Даже формально корректная отметка не доказывает реальное движение и не открывает сеанс.                                                                 |
| D-04 / E: датчик температуры и влажности    | Недоверенный |         2 | Не доказывает точность условий; проверяется применимость показания, а безопасный физический допуск определяется независимо.                             |
| D-05 / B: обычный контроллер батареи        | Недоверенный |         3 | Нет собственных полномочий активировать нагрев вне допуска C и аппаратной защиты.                                                                       |
| D-06 / A: обычный контроллер кондиционера   | Недоверенный |         3 | Нет собственных полномочий активировать охлаждение вне допуска C и аппаратной защиты.                                                                   |
| D-07 / U: обычный контроллер увлажнителя    | Недоверенный |         3 | Увлажнение возможно только при отдельном активном допуске C и исправной независимой защите.                                                             |
| D-08 / V: камера                            | Недоверенный |         3 | Прошивка и кодек не входят в базу доверия. При A-01 и A-04 камера обменивается данными по LAN только с M внутри хаба. |
| D-09 / W: пылесос                           | Недоверенный |         3 | Его статусы — сообщения устройства, а не независимое подтверждение.                                                                                     |

**Почему такой объём базы доверия.** Доверие всему D-01 включило бы сетевой стек и автоматику; доверие обычным устройствам добавило бы их прошивки. Одной фильтрации команд недостаточно: физический допуск может пережить программную команду, а сеанс выдачи данных требует отдельного владельца. T, Q, M и C разделены по полномочиям: удаление соответствующей проверяемой роли оставляет без контроля маршруты и статусы, источник команд, приватность или исполнительные выходы. Это обоснование минимизации по предложенному разбиению и выбранным инвариантам, а не оценка глобального минимума стоимости всех возможных проектов.
